# Component DB — база компонентов Altium на SQLite

База пассивных компонентов для Altium Designer (Database Library, `.DbLib`) в одном файле
SQLite и локальный веб-интерфейс, чтобы добавлять и править записи без Altium и без Access.

| Таблица | Что | Записей |
|---|---|---|
| `CAP_YAGEO` | керамические конденсаторы Yageo | 2190 |
| `RES_YAGEO_RC_L` | резисторы Yageo RC_L | 5318 |
| `IND` | ферритовые бусины и индуктивности (Murata, TDK, Taiyo Yuden) | 77 |

## Состав

```
GH_DB_LIB.sqlite        база (режим журнала WAL — см. «Altium и открытая база»)
GH_DB_SQLITE.DbLib      подключение Altium к базе
SCH/                    символы: CAP.SchLib, RES.SchLib, IND_DB.SchLib
PCB/                    футпринты: CAP.PcbLib, RES.PcbLib, IND.PcbLib
start.cmd / stop.cmd    запуск / остановка веб-интерфейса
app/
  main.py               веб-интерфейс (FastAPI)
  db.py                 схема, поиск, фильтры, запись, бэкапы
  backends.py           SQLite: соединения, снимки, состояние WAL, метаданные колонок
  footprints.py         имена футпринтов из .PcbLib
  assign_footprints.py  варианты футпринтов medium / HD / UHD по шаблону
  import_inductors.py   таблица IND: серии производителей с параметрами из документации
  ind_datasheets.py     ссылки на даташиты для IND
  make_dblib.py         держит GH_DB_SQLITE.DbLib в согласии с базой и папкой
  check_altium_connection.py  проверка подключения тем же путём, что и Altium
  config.json           путь к базе и библиотекам, настройки сервера
```

## Установка

1. **Python 3.10+.**
2. **64-битный ODBC-драйвер SQLite** — `sqliteodbc_w64.exe` с
   http://www.ch-werner.de/sqliteodbc/. Разрядность должна совпадать с Altium, а он
   64-битный.
3. Запустить `start.cmd`: поставит зависимости, пропишет в `.DbLib` путь к базе и откроет
   http://127.0.0.1:8777.
4. Проверить связку **до** захода в Altium:

   ```bash
   python app/check_altium_connection.py
   ```

   Скрипт подключается тем же путём, что и Altium (ADO / OLE DB через MSDASQL), и говорит, где
   рвётся: драйвер, строка подключения или запрос.
5. В Altium подключить `GH_DB_SQLITE.DbLib` (Components → ≡ → File-based Libraries
   Preferences → Install). В самом `.DbLib` выбран режим **Use Connection String** — для SQLite
   в списке «Select Database Type» подходящего пункта нет.

Папку можно переносить и клонировать куда угодно: пути в коде и `app/config.json`
относительные. Единственный абсолютный путь — к базе в строке подключения `.DbLib` (ODBC
считает относительный путь от рабочей папки Altium, а не от `.DbLib`), и его при каждом запуске
переписывает `start.cmd` через `app/make_dblib.py`, если папка переехала. Если библиотека в этот
момент открыта в Altium, переоткройте её.

Повторный запуск `start.cmd` перезапускает веб-интерфейс. Остановить — `stop.cmd`.

## Веб-интерфейс

- **Список и поиск.** Поиск по всем текстовым полям; несколько слов работают как «И»:
  `0402 100pF ±5%`. Сортировка — клик по заголовку.
- **Фильтры по столбцам** для полей, где не больше 60 разных значений. Складываются друг с
  другом и с поиском и **взаимно сужаются**: выбрали `Package = 2512` — в `Tolerance` останутся
  только реально встречающиеся значения. «(пусто)» отбирает незаполненные.
- **Добавление, правка, клонирование.** Форма строится из схемы таблицы, так что новая таблица
  подхватится без правки кода. «Клон» копирует запись, очищая `PartNumber` и номера поставщика.
  `PartNumber` и `Manufacturer` стоят рядом — это ключевые параметры детали.
- **Футпринты из `.PcbLib`.** `Footprint Ref 1–3` — выпадающие списки из самих библиотек.
  Значение, которого в библиотеке нет, помечено `⚠`; «✎ ввести вручную…» переключает поле в
  текстовый ввод.
- **Подсказки и автозаполнение.** Поля с небольшим числом значений подсказывают уже
  использованные; поля с единственным значением на таблицу подставляются в новую запись.
- **Проверки.** Дубликат `PartNumber` требует подтверждения; числа проверяются до записи.
- **Найти и заменить.** Массовая правка одной колонки в записях, отобранных поиском и
  фильтрами: часть значения, значение целиком (с пустым «Найти» — заполнить пустые) или
  регулярное выражение (`\1`). Сначала список «было → станет», запись — ровно его.
- **Футпринты** (вкладка). Отчёт и кнопка для `assign_footprints.py` — см. ниже.
- **Синхронизация** (справа вверху). Показывает, сколько сохранённого ещё лежит только в
  `-wal`, и переносит это в основной файл.
- **Резервные копии.** Перед первой записью за день и перед каждой массовой операцией база
  копируется в `backups/` (backup API SQLite — копия консистентна даже при записи).

Горячие клавиши: `/` — поиск, `Ctrl+S` — сохранить.

### Настройка — `app/config.json`

| Ключ | Назначение |
|---|---|
| `db_path` | Путь к базе; относительный — от папки проекта. |
| `library_path` | Где искать `.PcbLib`/`.SchLib`. Пусто — папка базы с подпапками, как у Altium. |
| `host` | `127.0.0.1` — только этот компьютер; `0.0.0.0` — доступ из локальной сети. |
| `port` | Порт, по умолчанию 8777. |
| `backup_on_write` | Дневной бэкап перед первой записью. Хранится 10 последних. |
| `open_browser` | Открывать браузер при старте. |

Переменные окружения `COMPONENT_DB_PATH` и `COMPONENT_DB_LIBRARIES` разово переопределяют
пути — удобно, чтобы потренироваться на копии базы.

## Схема базы

Все таблицы используют одни имена для одних данных — в основном так, как их называет DigiKey:
`PartNumber`, `Manufacturer`, `Description`, `Value`, `Tolerance`, `Package`,
`Size / Dimension`, `Height - Seated (Max)`, `Operating Temperature`, `Unit Price (USD)`,
`Supplier 1` / `Supplier Part Number 1`, `ComponentLink1URL` + `ComponentLink1Description`
(даташит открывается прямо с размещённой детали), `ImageURL`, `Category` / `CategorySub`,
`Zone`, и поля Altium: `Library Ref` / `Library Path`, `Footprint Ref` / `Footprint Path` и
`… 2`, `… 3` для вариантов плотности.

`ID` — `INTEGER PRIMARY KEY`, назначается сам. `PartNumber` — ключ поиска записи в `.DbLib`
(Single key lookup). В `RES_YAGEO_RC_L` два дубля `PartNumber` (`RC0402JR-07300KL`,
`RC1206JR-7W470RL`), поэтому индекс там обычный, а не уникальный.

## Варианты футпринтов по плотности монтажа

```bash
python app/assign_footprints.py            # показать, что изменится
python app/assign_footprints.py --apply    # записать
```

То же самое — вкладка «Футпринты» в веб-интерфейсе. Размер берётся из первого слова `Package`,
префикс — из `Category`:

| Колонка | Шаблон | Назначение |
|---|---|---|
| `Footprint Ref` | `CAP: 0201` | medium, по умолчанию |
| `Footprint Ref 2` | `CAP: 0201 HD` | high density |
| `Footprint Ref 3` | `CAP: 0201 UHD` | минимальная площадка, для ВЧ-линий |

Слот заполняется, только если футпринт есть в `.PcbLib`. medium — точное совпадение; HD и UHD
принимают и имя с хвостом (`CAP: 0402 HD C1005X04L`), если такое ровно одно. Чего нет — не
трогается и попадает в отчёт, так что библиотеку можно дополнять постепенно и запускать снова.

## Таблица IND

```bash
python app/import_inductors.py [--apply]   # серии производителей
python app/ind_datasheets.py   [--apply]   # ссылки на даташиты
```

Ряды целиком, параметры — из документации производителей (источник каждой серии указан в
начале `import_inductors.py`): Murata BLM03PX, BLM15EG, BLM15GG, LQH2MCN; TDK MMZ0603S;
Taiyo Yuden CB2012T и CBMF1608T — у Taiyo они переименованы в `LSQNA201212T…` / `LSQNB160808T…`,
старый номер записан в `Description`, поиск находит оба. Повторный запуск добавляет только
отсутствующие строки.

Даташиты берутся по приоритету Компэл (sds.compel.ru) → Промэлектроника → LCSC; у каждой
ссылки проверено, что PDF относится к этой детали или является каталогом серии, где она есть.

## Altium и открытая база

Пока библиотека загружена, Altium держит открытой транзакцию чтения. Поэтому база работает в
режиме **WAL**: запись идёт и при открытом Altium (в режиме `DELETE` её бы блокировало), а в
панели Components новые детали появляются после **F5**.

**Разместить новую деталь сразу после F5 нельзя** — встанет пустой символ без параметров и
футпринта. Размещение ищет запись через другое соединение Altium, и его открытая транзакция в
SQLite видит базу на момент своего начала. Настройками драйвера это не лечится: `NoTXN=1`
работает на любых других соединениях, Altium держит транзакцию в обход него.

**Обход:** после добавления деталей откройте `GH_DB_SQLITE.DbLib` в Altium и щёлкните в списке
**Table** по изменённой таблице — соединение пересоздаётся, и деталь размещается нормально.
Признак, что Altium ещё держит старое состояние: «Синхронизировать» переносит 0 страниц.

Если этот шаг надоест, настоящее решение — PostgreSQL: там каждый запрос видит свежие данные
(уровень READ COMMITTED), как было и с Access.

Что ещё нужно помнить:

- `GH_DB_LIB.sqlite-wal` и `-shm` — часть базы, пока её кто-то держит открытой. Копировать базу
  файлом можно, только закрыв Altium и веб-интерфейс, или брать копии из `backups/`.
- WAL не работает на сетевом диске.
- `LongNames=0` в строке подключения обязателен: с `1` драйвер отдаёт имена колонок как
  `CAP_YAGEO.PartNumber`, и Altium показывает имя таблицы в каждом параметре.
- Перед правкой `.DbLib` скриптом закройте его в Altium — иначе Altium запишет поверх свою
  версию.
- Спецсимволы через ODBC проходят без потерь: `±5%`, `-55°C ~ 125°C`, `0.013" (0.33mm)`.
